# fdo-squirrel-md-generator

A static, browser-only editor for `MD.cff` and `CITATION.cff` in the
[FDOx-squirrel](https://github.com/FDOx-squirrel/fdo-architecture) family of
tools for FAIR Digital Objects. No server, no build step at runtime, no
account — open the page, fill in a form, download a schema-valid `MD.cff`.

**Live:** once deployed, `https://fdox-squirrel.github.io/fdo-squirrel-md-generator/`
(see [Deploying](#deploying) below).

## What it does

- **Build an `MD.cff` from scratch**, validated live against
  [`fdo-squirrel`'s current `MD.cff-schema.yaml`](https://github.com/FDOx-squirrel/fdo-squirrel/blob/master/schemas/md_cff/MD.cff-schema.yaml)
  — fetched fresh on every page load, so the form is never validating
  against a stale copy of the schema.
- **Load an existing `MD.cff` back in** — drag and drop it onto the page
  (or a whole FDOx bundle `.zip`, e.g. `fdo-3d-packager`'s
  `dist/<slug>.zip`) and every field is populated for editing. This is the
  everyday round-trip: `fdo-3d-packager` writes a placeholder `MD.cff`
  with a fixed `TODO` identifier; this tool is where that gets fixed up
  before release.
- **Check a bundle `.zip`'s structure** — presence of `MD.cff` /
  `CITATION.cff` at the root, schema validity, a per-file role
  classification (via a vendored copy of `fdo-squirrel`'s own
  `classification_rules.yaml`), and a SHA-256 checksum for every file,
  cross-checked against `distributions[]` if `MD.cff` already lists any.
  This is a fast structural pre-check, **not** a replacement for
  `fdo-squirrel`'s own RDF/SHACL conformance check on ingest.
- **Derive `CITATION.cff`** automatically for `fdo:3DDataFDO` resources,
  following the mapping in `PRIMER.md`.
- A small interactive map (spatial extent: point and bounding box) and a
  full editor for temporal extent, heritage-object fields and technique/
  acquisition metadata.

Everything happens in your browser. The only network requests this page
makes are: the two schema fetches (`fdo-squirrel`'s `MD.cff-schema.yaml`,
same-origin copies of the vendored CFF schema and classification rules),
the four pinned CDN libraries, OpenStreetMap tiles if you open the map, and
— only when you press "look up coordinates" next to the Spatial extent
Identifier field — one request to either Wikidata's or OpenStreetMap's
(Nominatim) public API, to fetch that entity's coordinates. Nothing you
type or drop onto the page is sent anywhere otherwise.

## Using it

1. Open the page (deployed, or locally — see below).
2. Either fill in the form from scratch, or drop an `MD.cff` / bundle
   `.zip` onto the drop zone at the top.
3. Watch the **Validation** panel on the right; it updates as you type.
4. Download `MD.cff` (and, for `fdo:3DDataFDO`, the derived `CITATION.cff`)
   once it's valid.

Your in-progress form is autosaved to your browser's local storage as you
go (nothing leaves your machine) — reload the page and it offers to
restore your last draft.

## Local development

```bash
pip install -r requirements.txt
python main.py --strict      # renders docs/ from site/ + schemas/
python -m http.server --directory docs 8000
```

Then open `http://localhost:8000/`. Opening `docs/index.html` directly via
`file://` will **not** work — the schema/classification-rules fetches are
same-origin relative requests and browsers block those under `file://`.

`python main.py --strict` also lints `site/index.html` for floating
(`@latest`) CDN version references — every library pin has to be exact.

## Deploying

`docs/` is the GitHub Pages root, committed to the repository (it's fully
reproducible via `python main.py`, but Pages serves it directly, no CI
workflow needed): repository **Settings → Pages → Deploy from a branch →
`main` / `docs`**.

## Repository layout

```
main.py                    orchestrator (one step: build)
py/                         the build step + its Jinja2 template
site/                       hand-authored source: index.html, app.css, app.js
schemas/                    vendored CITATION.cff schema + classification_rules.yaml
docs/                       generated by `python main.py` — GitHub Pages root
```

See `PRIMER.md` for the full decision log (in German, per the family's
convention).
